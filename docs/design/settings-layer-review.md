# Settings layer design: independent review

Date: 2026-11-03. Reviewer: gemini-4-argon-high (agy), read only, against docs/design/settings-layer.md first version. Orchestrator checked two claims against the code (critical maturity sets the no-network sandbox; the CTO settings read serves only worker profiles); both hold.

Read-only design review. No files were changed and nothing was committed.

### 1. Can every one of the 149 inventory rows be expressed?
No. Five groups in `docs/design/modularity-inventory.md:108-258` cannot be expressed with `docs/design/settings-layer.md:10-28`:
- Missing float type ("Types are bool, int, duration, string, text, list and enum", `docs/design/settings-layer.md:10`): rows 58, 60, 68, 69, 72, 76, 77, 79, 81, 83, and 92 use float64 numbers (for example `Score float64` in `internal/gateway/scores.go:66` and `0.33` in `docs/design/modularity-inventory.md:192`).
- Dynamic maps, structured records, and directed edges: row 31 holds `CacheWindowSeconds map[string]int` per provider (`internal/gateway/cto_settings.go:104`). Rows 69 and 82 hold structured records keyed by model pattern or subject (`internal/gateway/store.go:252-257`). Rows 50 and 106 attach rules to `(source, target, kind)` edge pairs and `*` in `graph_edges` (`internal/gateway/store.go:191,199-202`), which single-node `Context{TeamID, RepoID, AgentID, RunID}` (`docs/design/settings-layer.md:51`) cannot address. Rows 120 and 126 are keyed per runtime-added skill or MCP server (`internal/gateway/store.go:124,556`), so one static Go table (`docs/design/settings-layer.md:42`) cannot pre-declare their keys.
- Cross-branch `repo -> agent` overrides: `docs/design/settings-layer.md:16` allows only `network -> team -> repo -> run` or `network -> team -> agent` ("Never silently combine two branches"). Rows 6, 42, 45, 128, and 131 have home `repo` and lowest override `agent` (and row 64 notes `repo, agent, or run`), which neither chain contains.
- Missing `session` and `machine` scopes: `docs/design/modularity.md:84,102` drops machine inheritance and draws `agent -> session`, while `docs/design/settings-layer.md:12,51` omits both. Today rows 21-24 and 52 vary per session (`sessions.delegation`) and per `(node_id, project)` (`project_policies`, `internal/gateway/store_policy.go:45,54,73`). Rows 53-59, 61, and 98 use per-machine `node.json` overrides (`internal/daemon/join.go:58-76`, and row 59 reads host RAM). Row 116 uses daemon `owner_preferences`, and rows 101 and 117 allow per-machine `integrations-local.json` (`internal/daemon/integrations.go:64`).
- Structural, prose-tightened, procedural, and repo-file rows: row 41 is the repo/agent entity split itself (`internal/gateway/store_graph.go:26-47`). Row 42 marks `escalate` as advice (free replacement, `docs/design/settings-layer.md:18`), violating `docs/design/modularity.md:61` ("an agent may add stricter escalation for itself, never looser"), while prose rules only allow equality (`docs/design/settings-layer.md:26`). Rows 34, 62, 76, and 96 encode algorithms or formulas, and row 136 reads `.agent-net/worker.md` from disk.

### 2. Is the resolution and tightening logic sound?
Not yet. Three concrete failures show up against current code:
- Lower level loosening a rule: Today `critical` maturity sets `worker_sandbox` to `no-network` (`internal/protocol/maturity.go:112-113`). Under `docs/design/settings-layer.md:18` ("Start with the shipped default, then visit allowed levels"), if `workers.sandbox_level` (row 52) starts at network default `sandboxed` and a `critical` repo has no explicit `setting_values` row, a `run` override of `sandboxed` matches the network parent and loosens `no-network`. If a conditional default function (`docs/design/settings-layer.md:10`) instead reads `RepoID=critical` at the root, a `team` override of `sandboxed` is falsely rejected as looser than its child. Also, rows 42 and 128 are marked `advice`, letting an agent replace `merge_authority: ask` with `full` (`internal/protocol/trust.go:37-50`), and editing a node's `maturity` or `team` edge bypasses `setting_values` ancestor write checks (`docs/design/settings-layer.md:18`).
- Conflicting rules: Splitting coupled settings loses joint invariants. Setting `workers.auto_continue=true` (row 64) conflicts with `workers.auto_continue_max=0` (row 65). Tightening `workers.isolation_minimum=worktree` (row 51) conflicts with continuing a worktree-less run (`internal/daemon/worker_continue.go:60-64`) and read-only `isolation: "none"` (`internal/mcpserver/cto.go:133`). Row 129 already conflicts between `MergeApprovalFor` ("ask the owner", `internal/protocol/maturity.go:286`) and `MergeAuthorityForSession` (`full`, `internal/gateway/graphread.go:144`).
- "Fail closed" breaking normal use: Today `policyCall` (`internal/daemon/policy.go:75-80,178-188`) and `graphOf` (`internal/daemon/graphread.go:63-67`) return empty results when the gateway is down >10m or before `session.sync` assigns `sid`, keeping local Claude, OpenCode, and Pi turns working. `NodeDefaults` (`internal/protocol/maturity.go:125-127`) ignores invalid stored rows instead of breaking `msg.send` or worker starts. Judge errors fall back to `normal` (row 89), and daemon startup (`internal/daemon/daemon.go:136`) and `harnessUpdatesAllowed` (`internal/daemon/harness_update.go:22-31`) run before any gateway link. Failing closed on unresolved rules or invalid persisted rows (`docs/design/settings-layer.md:18,60`) breaks offline turns, message delivery, and daemon startup.

### 3. Storage choice and cutover breakage
A new `setting_values` table with gradual cutover is the right call. `owner_settings` (`internal/gateway/store.go:186-187`) lacks scope, actor, and revision and stores operational state like `cto_session` (`internal/gateway/proposal_validate.go:202`) and `worker_rotation`. `graph_node_settings` (`internal/gateway/store.go:204`) is string-only, lowercased (`internal/gateway/store_graph.go:228`), conflates repo and agent, and misses `project_policies` (`internal/gateway/store.go:164`).
What breaks during cutover:
- Graph history and undo: `SetNodeSetting`, `RemoveArchitect`, and `GraphUndo` read and write `graph_node_settings` and `graph_history` directly (`internal/gateway/store_graph.go:142-167,257,401-418,467`). Migrating node settings without updating `GraphUndo` breaks undo or revives dead rows.
- Old daemons and a Mac on an older version: Gateway `hello` (`internal/gateway/server.go:708-725`) does not negotiate versions (`internal/daemon/compat_test.go:21-80`). Rejecting older daemons at `hello` (`docs/design/settings-layer.md:42`) deadlocks `autoUpgrade` (`internal/daemon/link.go:348`), which starts only after `hello` and `session.sync` finish (`internal/daemon/link.go:285-348`). While an older Mac runs, it calls legacy HTTP and WS endpoints (`/v1/integrations`, `/v1/scores`, `/v1/cto-settings`, `policy.get`, `graph.read` in `internal/gateway/scores.go:32-240` and `internal/gateway/cto_settings.go:115`) and enforces local binary constants for worker limits and guidance, ignoring `setting_values` overrides unless legacy handlers translate from `setting_values`.
- Rollback: Stopping dual-write with forward-only `schema_version` (`internal/gateway/store.go:651-660`) drops post-cutover edits on binary rollback.

### 4. Resolver API for the daemon and offline behavior
The API is wrong for the daemon. Per-key `Resolve` RPCs (`docs/design/settings-layer.md:54-60`) add round-trips to 2s turn hooks (`internal/daemon/policy.go:63`) and 5s worker ticks (`internal/daemon/workers.go:103`), while `ResolveAll` evaluates ~149 keys when callers need a few. Local callers know `sessionID`, `harness`, and `project`, not `TeamID` or `AgentID` (`docs/design/settings-layer.md:51`), and `Context` lacks `NodeID` and `Harness`. Also, `docs/design/settings-layer.md:60` contradicts itself: "no stale cache may relax enforcement" forbids any offline cache when the gateway tightens a rule while unreachable, clashing with "Preserve existing operation when the gateway is unavailable".
Offline, the daemon should persist the last versioned gateway snapshot in `daemon.db` (pushed on `hello` and invalidation frames, like `mcp.sync` in `internal/daemon/link.go:186`). Fail closed only for gateway-dependent mutations (worker picker start, cross-node send, proposals). Run local worker timeouts, cleanup, caller checks, and local session turns from the persisted snapshot (or shipped defaults before first sync).

### 5. Guidance fixtures and runtime-dependent text
Byte fixtures of `guidance.Block` for `claude`, `other`, and `combined` (`internal/guidance/guidance.go:20-36`) only prove static default `Block` output. They miss:
- File sync, scope, and uninstall: `SyncGuidance` (`internal/agentfiles/agentfiles.go:261-299`) promotes shared symlinks to `Combined`. `RemoveAntigravity` (`internal/agentfiles/antigravity.go:32,146-164`) checks `bytes.Equal` against default `Block(Other)` and leaves `rules/AGENTS.md` behind on uninstall if advice text changes. User-global `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md` (`internal/agentfiles/agentfiles.go:88-94`) cannot render repo or agent overrides (`docs/design/settings-layer.md:34`) without leaking across repos. `findLegacy` and `findMarked` (`internal/guidance/guidance.go:88-130`) break if heading or markers change, and duplicate advice in `internal/toolcatalog/tools.go:22-29` and TS plugins is untested.
- Runtime-dependent text: `docs/design/settings-layer.md:10` bans templates while line 74 says "preserving templates and conditional text". Static fixtures miss `PolicyText` (`agentID` and `coder` model at `internal/protocol/delegation.go:278-293`), `RulesText` and `MergeApprovalFor` (empty when maturity unset, live delegate names at `internal/protocol/maturity.go:254-305`), `AuthorityNote` and `OwnerInstructionNote` (receiver merge rule, prompt excerpt, and TS copies at `internal/protocol/trust.go:46-54,88-90` and `internal/protocol/maturity.go:210-211`), and `WorkerTaskBodyWithCharter` and `FormatWorkerNotice` (harness, permissions, worktree, diff, rate ask at `internal/protocol/workers.go:546-595,786-856`).

### 6. What is missing for step 3 (build resolver and storage with no callers)?
- Exact SQLite schema and invariants: canonical `network` scope ID, `repo` scope ID case rule (`graph_nodes` is case-sensitive at `internal/gateway/store_graph.go:640` vs lowercased `project_policies` at `internal/gateway/store_policy.go:23`), global monotonic revision for snapshots, `Value` encoding (including `float` and empty list vs absent row), and an append-only `setting_history` table.
- Scope-lookup interface: how the resolver validates `Context` while `team` and `agent` tables do not exist and component repos may exist only implicitly in `projects` or `sessions` (`internal/gateway/store_graph.go:38-46,605-608`).
- Level-bound conditional default contract: deterministic input struct (`maturity`, `harness`, `ram_bytes`) and binding conditional defaults at their home level (`repo`) rather than root.
- CTO visibility and atomic proposal revisions (before wiring callers): `docs/design/settings-layer.md:64` cites a CTO `settings` read in `internal/mcpserver/cto_v2.go`, which is not there; `settings` lives in `internal/mcpserver/cto.go:72`, and `internal/daemon/cto_reads.go:97-108` rejects everything except `worker_profiles` under CTO read-scope parity (`internal/mcpserver/cto_public_test.go:17`, `docs/design/modularity-inventory.md:272`). Definitions need a `visibility` field. Also, `internal/daemon/proposals.go:293,472-475` stores proposals in daemon SQLite and runs `validate` then `run` separately, so `expected_revision` must be checked atomically inside the gateway write RPC.

### 7. Top 5 changes to the design (most important first)
1. Expand types, scopes, and chains: add `float` and entity/map-keyed settings (skills, MCP servers, scores, edges), support `repo -> agent -> session/run` inheritance (rows 6, 42, 45, 128, 131), and pass `SessionID`, `Harness`, and `NodeID` into resolution.
2. Bind conditional defaults at their home level: evaluate `repo.maturity` presets at the `repo` step during traversal, revalidate descendants on `maturity` and `team` edge changes, and turn `escalate` and `merge_gate` from free-replacement advice into additive/ordered rules.
3. Replace daemon per-key RPCs and blanket fail-closed with a gateway-pushed snapshot in `daemon.db`: fail closed only on gateway mutations, keep offline local turns and worker supervision working, and keep `hello` open so `autoUpgrade` (`internal/daemon/link.go:348`) cannot deadlock.
4. Add definition `visibility`, `setting_history`, and gateway-atomic `expected_revision`: mark which settings the CTO and agents may read (`internal/daemon/cto_reads.go:106`, `internal/mcpserver/cto_public_test.go:17`), preserve `GraphUndo` parity, and check revision plus tightening in one gateway SQLite transaction on approval.
5. Restrict user-global `CLAUDE.md` and `AGENTS.md` to `network` advice and use typed text slots: inject `team`, `repo`, and `agent` advice per turn or brief, update `RemoveAntigravity` (`internal/agentfiles/antigravity.go:162`) to match markers instead of default bytes, and test slot rendering across Go and TypeScript copies.
