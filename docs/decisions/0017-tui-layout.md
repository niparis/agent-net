# 0017 - The TUI main table: stable rows, filters and task names

**Date:** 2026-10-30
**Status:** Built on branch `agent-net/w_0f977af31650e85b`. Proposed until the owner has read it.
**Context:** The owner reads `agent-net tui` to see what needs them, what each session is doing and what sessions say to each other. The main table sorted rows by name and status, so a row moved when a session changed, and FUNCTION (the project description) pushed the useful TASK out. This is part A of the agreed TUI design (part B is the message feed, part C is "Needs you").

## Decisions

1. **One column order:** NAME, AGENT, PROJECT, MODEL, STATUS, TRUST, POLICY, CPU, RAM, TASK. TRUST is always there. POLICY stays conditional on some session having a delegation policy ([0014](0014-delegation-policy.md)), because an empty column only takes room. TASK takes the width that is left, and is cut with `...`. BRANCH, MODE, PROC and FUNCTION move to the detail pane. The detail pane also says where the project is known from, in words: `project source: seen in a session`, `registered`, or `seen in a session and registered`.
2. **TASK** is the task the session announced (`agent_announce`, `Profile.Task`). A session that never announced shows its harness title when that differs from NAME, and otherwise nothing: blank, not `-`, and never the old `no AGENTS.md`.
3. **No sorting by name or status.** The gateway stores `created_at` for a session when it first sees it (migration 15, after `sessions.worker_started` and the tools columns; existing rows take `last_seen`), and the agent list carries it as `first_seen`. The table orders sessions by `first_seen`, oldest first, so a new session appears at the bottom of its machine and no activity moves a row. Workers stay under their caller, ordered by start time. Machines keep this machine first, then by name.
4. **Filters replace re-ordering.** `/` is the text filter as before. `a` is new: active only, which hides sessions that are idle and whose last report is more than an hour old. `o` still shows offline and dormant sessions. The title line lists the active filters (`filter: active, /cogforge`), and each machine heading says how many sessions the active filter hides. An idle session older than an hour is drawn dim in every mode.
5. **Service rows are gone.** A tree that several sessions share used to have a row of its own, after the machine's sessions; it no longer does. The shared OpenCode service is a short dim note in its machine line (`opencode service 2.1G 9 procs`), and its process list stays in the detail pane of a session that uses it. A tree marked shared with exactly one session is that session's own private server, so its CPU and memory are on that row, not `shared`.
6. **Worker names come from the task, not the worker ID.** The daemon records the task summary with the worker, and `WorkerInfo` now carries it in the agent list (`WorkerLaunch.Task` to `WorkerInfo.Task`, cut by `protocol.WorkerTaskSummary`). The row after the tree marker is the task; the full worker ID is on the detail pane's `id` line. This is better than naming the session after the task: a plugin's report cannot overwrite a row name, and every machine gets the same task through the gateway. When the task is missing (an older machine or gateway), the row says `worker <harness> <short worker id>`.
7. **The list uses its height.** The table grows to its content before the detail pane and the feed take the rest, so there is no empty gap between the list and the detail pane.

## Why the gateway, not the session name

The task travels with the worker in the agent list (`sessions.worker` JSON), so a TUI on any machine shows it. Setting the session's `Name` instead would fight the plugin that reports the name, and would not help an older gateway. `Title` in the agent list is the name the harness gave the session before an agent announced one; it is the fallback for TASK.
